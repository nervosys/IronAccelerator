# Direct3D 12 backend

Crate: `ironaccelerator-dx12`. Dependencies: `libloading`, `once_cell`.

Covers the one GPU API on Windows no other backend in this workspace
reaches. NVIDIA, AMD, Intel, and Qualcomm parts all expose D3D12 on
Windows whether or not a Vulkan ICD is installed, and on Arm-based
Windows devices it is frequently the only path available.

## Build time

Nothing. `d3d12.dll` and `dxgi.dll` are resolved with `libloading`, never
linked, so the crate builds on every target — including non-Windows,
where the candidate list is empty and the backend simply reports
unavailable.

The COM layer is hand-written: the vtable layout for `IDXGIFactory1`,
`IDXGIAdapter1`, and `ID3D12Device` is declared directly and called
through. Slots that are never invoked are typed as opaque pointers, which
keeps the layout correct without a full COM binding crate. **Slot order is
load-bearing** — it mirrors the COM inheritance chain and must not be
reordered.

`windows-sys` is not used: it dropped its Direct3D bindings in 0.60, and
the `windows` crate would link rather than load.

## Runtime

- Windows 10 1507+ with a D3D12-capable driver.
- Any vendor. Software adapters (WARP) are enumerated by DXGI but
  filtered out — a rasteriser is a correctness reference, not an
  accelerator.

## Capabilities

Probed per adapter via `ID3D12Device::CheckFeatureSupport`:

| Source                              | Surfaced as                    |
|-------------------------------------|--------------------------------|
| `FEATURE_LEVELS.MaxSupported`       | `arch` (`d3d12_2-2203`)        |
| `OPTIONS.DoublePrecisionFloatShaderOps` | `FP64`                     |
| `OPTIONS4.Native16BitShaderOpsSupported` | `FP16`                    |
| `ARCHITECTURE1.UMA`                 | `UNIFIED_MEMORY`, `Mobile` tier |
| `OPTIONS1.WaveOps` + lane counts    | recorded, not mapped to a flag |
| `DXGI_ADAPTER_DESC1`                | name, vendor, VRAM             |

Deliberately conservative. D3D12 has no query for INT8 dot product or for
matrix/tensor units, so those bits stay clear even on hardware that has
them — a false negative is recoverable, a false positive is not.

Two specific judgement calls:

- **`WMMA` is not set from `WaveOps`.** Wave intrinsics are cross-lane
  shuffles, not a matrix engine. (The pre-2.0.0 WebGPU backend made this
  conflation; it was wrong there too.)
- **Min-precision 16-bit does not set `FP16`.** `OPTIONS.MinPrecisionSupport`
  is a storage hint the driver may satisfy at FP32. Only
  `Native16BitShaderOpsSupported` means real half-precision math. Both are
  recorded on `EnumeratedAdapter` if you want to distinguish them.

`multiprocessor_count` and `clock_khz` stay 0: D3D12 exposes neither.
`total_lane_count` is available on `EnumeratedAdapter` and is the closest
signal, but it measures total width rather than a unit count, so it is not
reported as one.

## Compute submission

`compute::Context` wraps a COMPUTE queue, command allocator, command list,
and fence. It provides:

- `device_buffer` / `upload_buffer` / `readback_buffer` — committed
  resources in the DEFAULT / UPLOAD / READBACK heaps.
- `upload` / `download` — staged copies with the resource barriers and
  fence wait handled.
- `root_signature_with_uavs(n)` — a root signature with `n` root UAVs at
  `u0..un`; or `root_signature_from_blob` to take the one a shader
  declares via `[RootSignature(...)]`.
- `compute_pipeline(root, dxil)` and `dispatch(...)`.

### Binding model

Buffers bind through **root UAV descriptors**, not descriptor tables. A root
descriptor takes a raw GPU virtual address, so there is no descriptor heap —
and, more to the point, no call to `GetCPUDescriptorHandleForHeapStart`, which
returns a small struct by value and is a well-known ABI trap for hand-written
D3D12 bindings. This covers the flat `RWStructuredBuffer` /
`RWByteAddressBuffer` case that compute kernels overwhelmingly use. Textures
and samplers would need the heap path and are not supported.

### Shaders

Not compiled here — bring DXIL, as the CUDA backend takes PTX:

```
dxc -T cs_6_0 -E main kernel.hlsl -Fo kernel.dxil
```

**`dxc` only signs its output when `dxil.dll` sits beside it, and D3D12
rejects unsigned DXIL with `E_INVALIDARG`.** The Windows SDK ships the pair;
the Vulkan SDK's `dxc` does not, and it is usually the one that wins on PATH.

## Not provided

Descriptor heaps, textures, samplers, graphics pipelines, multi-queue
scheduling, and a `MemPool` equivalent. `Context` submits one command list at
a time and blocks on a fence.

## Verifying

```
cargo run -p ironaccelerator-dx12 --example list_adapters
```

Prints every adapter with its probed feature bits. Ordinals are dense and
match `Runtime::devices()` order; `drv::open` uses the same filter as
`drv::enumerate`, so the two agree.

```
cargo test -p ironaccelerator-dx12
```

`tests/dispatch.rs` compiles a kernel with `dxc` and runs it on every
adapter, which is what proves the hand-written vtables are laid out
correctly — a wrong slot index shows up there as a failed `HRESULT` or a
wrong answer, never as a compile error. It skips with a printed reason when
there is no adapter or no `dxc`. Set `IA_DX12_SHADER` to a precompiled blob
to bypass `dxc`.
